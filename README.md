# Codex Usage Tracker

一个轻量的本地 Codex 多账号用量记录器。后端定时读取各账号的订阅用量并保存历史快照，浏览器通过可视化面板查看各账号当前的已用额度和历史变化。

项目仅使用 Node.js 内置模块，不需要数据库，也没有第三方运行时依赖。

## 功能概览

- 管理多个 Codex / ChatGPT 账号，每个账号独立保存凭据和历史
- 暂停或恢复单个账号的查询，暂停不会删除账号和历史
- 定时采样，也可手动查询单个账号或刷新全部启用账号
- 显示账号状态、各用量窗口的已用与剩余额度、重置倒计时、附加额度（如特定模型的独立限额）和凭据过期时间
- 数据过期或用量窗口已重置时明确标出，不把旧数据当作当前状态
- 历史曲线按最近 24 小时、7 天、30 天或全部记录筛选，停机造成的数据缺口会断开显示
- 图表支持自适应纵轴和固定 0%～100% 纵轴，可点击图例显示或隐藏账号，也可切换为表格视图
- 页面跟随系统使用浅色或深色主题
- 普通用户与管理员模式分离
- 每个账号最多保留最近 20,000 条快照
- JSON 数据使用临时文件原子替换，降低中途退出造成文件损坏的风险

## 工作方式

后端和网页有两套独立的定时机制：

1. Node.js 后端按照配置的间隔查询用量接口并保存快照。
2. 网页在可见时每 30 秒读取一次后端已有状态并更新界面；隐藏的页面跳过定时同步，重新切回页面时立即同步。

打开多个浏览器或标签页只会增加本地状态读取，不会为每个页面创建新的后台采样定时器。页面上的“查询”和“刷新全部”会主动要求后端立即采样；同一账号正在查询时，后端会拒绝重复并发查询。

## 环境要求

- Node.js 18 或更高版本，建议使用当前 LTS 版本或 Node.js 24
- 服务器能够访问 `https://chatgpt.com`
- 运行进程对项目的 `data/` 目录具有读写权限

检查 Node.js 版本：

```bash
node --version
```

## 快速启动

### 1. 获取代码

```bash
git clone https://github.com/lkdhy/codex-usage-tracker.git
cd codex-usage-tracker
```

项目没有第三方运行时依赖，因此不需要执行 `npm install`。

### 2. 设置管理员密码并启动

密码通过 `CODEX_ADMIN_PASSWORD` 环境变量传给进程，不应写进代码或将被提交的文件。

Windows CMD：

```cmd
set "CODEX_ADMIN_PASSWORD=你的密码"
npm start
```

Windows PowerShell：

```powershell
$env:CODEX_ADMIN_PASSWORD = '你的密码'
npm start
```

Linux / macOS：

```bash
export CODEX_ADMIN_PASSWORD='你的密码'
npm start
```

以上写法只对当前终端和由它启动的进程生效。程序不会自动读取 `.env` 文件。

### 3. 打开网页

访问：

```text
http://127.0.0.1:4782
```

服务默认只监听 `127.0.0.1`，其他电脑无法直接访问。

## 添加账号

1. 点击右上角“管理员登录”。
2. 输入启动服务时设置的管理员密码。
3. 点击“添加账号”。
4. 填写便于识别的账号名称。
5. 粘贴该账号 `auth.json` 的完整 JSON 内容并保存。
6. 点击账号卡片上的“查询”，或等待后台自动采样。

程序不会读取或修改用户主目录中的 `.codex/auth.json`，也不会在编辑账号时向网页回填 token。粘贴的凭据由后端分别保存到 `data/accounts/`。

页面提示的凭据常见位置是 Linux / macOS 的 `~/.codex/auth.json`，以及 Windows 的 `%USERPROFILE%\.codex\auth.json`。如果你的凭据保存在其他位置，请使用对应文件。

导入的 JSON 必须包含顶层 `access_token` 或 `tokens.access_token`；仅含 API Key 的 JSON 不满足当前导入要求。账号 ID 支持顶层 `account_id` 或 `tokens.account_id`。保存时只检查本地凭据结构，token 是否仍可使用需要实际查询确认。

程序不会自动刷新 token。凭据过期后，需要在管理员模式中编辑账号，粘贴更新后的 `auth.json`。编辑时留空凭据字段会保留原有凭据。

每个账号绑定首次查询到的远程账号。编辑账号更换凭据时，如果新旧 `auth.json` 中的 `account_id` 不同，保存会被拒绝；无法预先判断时，后续查询发现远程账号变化也会拒绝写入快照，避免不同账号的历史混在一起。如需记录另一个 ChatGPT 账号，请新建账号。

## 普通用户与管理员

未登录或会话过期时，页面处于普通用户模式；已有有效管理员会话时会自动恢复管理员模式。普通用户可以：

- 查看账号状态和历史图表（含表格视图）
- 调整历史范围和纵轴范围，通过图例显示或隐藏账号
- 查询单个账号
- 刷新全部启用账号

管理员登录后还可以：

- 添加、编辑和删除账号
- 更新账号凭据
- 暂停或恢复账号的查询
- 开关自动查询，修改查询间隔和请求超时

普通用户看不到管理入口，对应接口也由后端校验。管理员会话使用 `HttpOnly`、`SameSite=Strict` Cookie，有效期为 8 小时。服务重启会清空会话，需要重新登录；同一浏览器配置中的多个页面通常共享该 Cookie。

## 自动查询

默认每 5 分钟查询一次，单次请求超时默认为 10 秒。管理员可在“自动查询设置”中开关自动查询，并修改查询间隔（1～1440 分钟）和单次请求超时（1～120 秒）。

当前实现会在每次服务启动后立即执行一轮查询，即使已关闭自动查询也会执行。自动查询开关只控制后续的定时查询，不限制手动查询，也不会取消已经开始的请求。

批量查询逐个处理已启用且本地存在 access_token 的账号，一个账号超时会延后后续账号的查询。本地存在 token 不代表它尚未过期或已通过上游验证。没有可用 token 的账号会被跳过，不会被记作查询失败。上游请求、响应解析或账号身份校验失败时，只更新账号的最后错误状态，不会将失败响应写成用量快照。

账号的“暂停查询”和“删除”是两种不同操作。暂停只会将账号移出自动查询、刷新全部和单账号查询，账号凭据、账号信息和历史快照都会保留；恢复后会继续使用原有历史。删除账号则会同时删除该账号的凭据和全部历史快照。

暂停账号不会取消已经发出的请求，该次查询仍可能保存结果。账号若在查询期间被删除，返回的结果不会写入历史。

## 图表与表格

历史曲线展示各账号**主额度窗口的已用百分比**，其他用量窗口和附加额度在账号卡片中查看。不同账号的主窗口长度可能不同，比较曲线时应同时查看窗口说明。

- 时间范围支持最近 24 小时、7 天、30 天或全部历史；筛选不会删除历史记录。
- 自适应纵轴根据当前可见数据调整范围，便于观察小幅变化；固定 0%～100% 纵轴便于比较绝对额度水平。
- 曲线连接实际采样点，不做平滑拟合；中间连线不代表额外采集的数据。长时间没有记录的区间会断开，当前断线阈值显示在图表下方。
- 鼠标悬停可查看最近记录，图表获得键盘焦点后可用左右方向键查看相邻采样时刻。多个账号的提示值取自附近的记录，不保证完全同时采样。
- 表格展示所选时间范围内的汇总值：24 小时视图按小时取最高值，其他视图按天取最高值，均使用浏览器本地时间分组，最新的在前；表格不是逐条快照列表。
- 时间范围、纵轴模式、图例隐藏状态和表格开关保存在浏览器本地，刷新后会恢复。

页面底部的 GitHub 入口会在新标签页打开项目仓库。

## 运行日志

日志每行以服务进程的本地时间开头，`[INFO]` 为正常事件，写入标准输出（stdout）；`[WARN]` 为失败或异常，写入标准错误（stderr）。上游请求日志记录请求方法和接口地址，收到响应时记录 HTTP 状态码；网络连接失败或超时且尚未收到响应时，没有可记录的上游状态码：

```text
2026-09-15 16:01:49.007 [INFO] Codex Usage Tracker: http://127.0.0.1:4782
2026-09-15 16:01:49.007 [INFO] 管理员密码已配置 · 已保存 4 个账号 · 0 条快照
2026-09-15 16:01:49.008 [INFO] 发起请求 正常账号：GET https://chatgpt.com/backend-api/wham/usage
2026-09-15 16:01:49.042 [INFO] 调用接口 GET https://chatgpt.com/backend-api/wham/usage → 200
2026-09-15 16:01:49.047 [INFO] 已记录快照：GET https://chatgpt.com/backend-api/wham/usage 返回 200 · 已用额度 42% · 该账号 1 条
2026-09-15 16:01:49.048 [INFO] 采样成功 正常账号：耗时 41ms
2026-09-15 16:01:49.052 [INFO] 调用接口 GET https://chatgpt.com/backend-api/wham/usage → 401
2026-09-15 16:01:49.057 [WARN] 请求失败 凭据失效账号：GET https://chatgpt.com/backend-api/wham/usage · 登录凭据已失效…（HTTP 401） [AUTH_EXPIRED]
2026-09-15 16:01:49.074 [WARN] 请求失败 结构异常账号：GET https://chatgpt.com/backend-api/wham/usage · 用量接口响应结构已变化… [UPSTREAM_SCHEMA]
2026-09-15 16:01:49.075 [INFO] 首次查询完成：成功 1 · 跳过 1 · 失败 2 · …
```

记录的内容：

- 启动信息：监听地址、管理员密码是否配置、已加载的账号和快照数量
- 自动查询的开启/关闭，以及每次自动查询的开始和结果汇总
- 每个账号的采样过程：发起请求、上游返回的状态码、写入快照或失败原因（含错误码）
- 收到 `POST /api/poll` 及其结果汇总
- 自动查询设置的变更内容（旧值 → 新值）
- 本地 HTTP 请求的完成日志：非 GET 请求及返回 4xx/5xx 的请求会记录状态码和耗时；异常详情可能另外输出一行

以下是常见的采样和账号操作错误码，可结合日志、账号卡片或操作提示定位问题：

| 错误码 | 含义 |
| --- | --- |
| `AUTH_EXPIRED` | 上游返回 401，凭据已失效 |
| `UPSTREAM_FORBIDDEN` / `UPSTREAM_ENDPOINT` / `UPSTREAM_RATE_LIMIT` | 上游返回 403 / 404 / 429 |
| `UPSTREAM_HTTP` | 上游返回其他异常状态 |
| `UPSTREAM_NETWORK` / `UPSTREAM_TIMEOUT` | 无法连接或请求超时 |
| `UPSTREAM_FORMAT` / `UPSTREAM_SCHEMA` | 响应不是有效 JSON，或结构无法识别 |
| `CREDENTIALS_MISSING` | 本地没有可用 access_token，未发起请求 |
| `ACCOUNT_MISMATCH` | 编辑凭据时发现新旧 account_id 不同，拒绝保存 |
| `ACCOUNT_PAUSED` | 账号已暂停，拒绝发起查询 |
| `POLL_IN_PROGRESS` / `ACCOUNT_NOT_FOUND` | 该账号正在查询 / 账号不存在或已在查询期间被删除 |
| `POLL_FAILED` | 账号状态和采样失败日志中的兜底错误码，包括查询时发现远程账号与绑定不符 |
| `UPSTREAM_ERROR` | 未指定专用错误码时，服务器请求错误的默认码 |
| `INTERNAL_ERROR` | HTTP 错误响应中的兜底错误码 |

编辑凭据时检查出的账号不匹配返回 HTTP 409 和 `ACCOUNT_MISMATCH`；查询期间发现远程账号变化时，当前实现记录 `POLL_FAILED`，单账号查询的 HTTP 响应为 500 和 `INTERNAL_ERROR`，两种情况都不会写入该次用量快照。

**成功的 GET 请求不会输出请求完成日志**，包括页面定时读取的 `/api/state` 和 `/api/session`；非 GET 请求和所有出错请求都会记录。请求路径日志不包含查询串。程序不自行写日志文件或轮转，由终端或进程管理器收集 stdout 和 stderr，例如 systemd 可用 `journalctl -u codex-usage-tracker -f` 查看。

重定向输出时应同时检查 stdout 和 stderr 的去向。终端没有日志可能是输出被转存、收集工具延迟显示或服务未成功启动，不能仅据此判断为缓冲问题。

## 数据文件

程序首次启动时会自动创建 `data/`：

| 路径 | 内容 | 敏感性 |
| --- | --- | --- |
| `data/accounts.json` | 账号名称、状态、邮箱、远程账号 ID 等元数据 | 可能包含个人信息 |
| `data/accounts/<账号ID>.json` | 每个账号的完整认证凭据 | 包含访问凭据 |
| `data/snapshots.json` | 按账号保存的历史用量快照 | 可能包含账号和订阅信息 |
| `data/config.json` | 自动查询间隔和请求超时等配置 | 通常不敏感 |
| `data/meta.json` | 数据格式版本，确保旧版数据迁移只执行一次 | 不敏感 |

整个 `data/` 已被 `.gitignore` 排除，不会随正常的 `git add .` 提交。管理员密码也不保存在这些文件中。

每个账号独立保留最近 20,000 条快照。一个账号达到上限时，只淘汰该账号最旧的记录，不会挤占其他账号的历史容量。

## 备份与迁移

Git 仓库只负责代码，`data/` 需要单独备份。迁移到另一台 Windows 或 Linux 主机时：

1. 停止源主机上的服务，避免复制过程中仍有文件写入。
2. 在目标主机克隆或复制项目代码。
3. 将源项目中的整个 `data/` 安全复制到目标项目根目录。
4. 确认目标运行用户对 `data/` 及其子目录有读写权限。
5. 在目标主机重新设置 `CODEX_ADMIN_PASSWORD`。
6. 启动服务并检查账号状态。

请使用安全通道传输 `data/`，其中包含可用的登录凭据。不要通过公开 Git 仓库、公开网盘或聊天消息传输。

从旧版数据升级时，如果只有 `data/snapshots.json` 而没有 `data/accounts.json`，程序会尝试创建账号记录并根据历史中的远程账号 ID 拆分数据。当前版本迁移完成后会在 `data/meta.json` 中记录格式版本，后续启动不会重复执行这次迁移；正常的启动查询和后续采样仍会更新账号状态与历史数据。旧版绑定用户目录 `auth.json` 的凭据不会被自动读取，需要重新设置。

## Linux 常驻运行

可以使用 systemd 管理进程。路径和用户请按实际环境修改：

```ini
[Unit]
Description=Codex Usage Tracker
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=codex
WorkingDirectory=/opt/codex-usage-tracker
Environment=CODEX_ADMIN_PASSWORD=请替换为实际密码
ExecStart=/usr/bin/node server.js
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

包含真实密码的 service 文件应限制读取权限。也可以使用 systemd 的 `EnvironmentFile`，并确保该文件不在 Git 仓库内。

当前代码固定监听 `127.0.0.1:4782`。如需从其他电脑访问，建议保留本地监听，通过 Nginx 或 Caddy 反向代理，并配置 HTTPS 和额外访问控制。管理员登录目前没有失败次数限制，不建议直接将 4782 端口暴露到公网。

## 常见问题

### 管理员登录一直提示密码错误

确认环境变量和 `npm start` 在同一个终端中执行。使用 `setx` 设置 Windows 用户环境变量后，需要关闭并重新打开终端。修改环境变量后必须重启 Node.js 服务。

### 启动后终端没有任何输出

先确认服务真的在运行：

```text
2026-09-15 15:57:42.895 [INFO] Codex Usage Tracker: http://127.0.0.1:4782
```

服务成功监听后会打印上面这一行。如果看不到，请检查进程是否启动成功，以及 stdout、stderr 是否被重定向到文件或进程管理器。成功的页面状态同步不记录日志；每轮自动查询会输出开始、各账号的请求与结果，以及结束汇总。没有其他操作时，两轮查询之间长时间没有输出是正常的。

### 页面数据为什么不是立即变化

可见网页每 30 秒同步一次后端已有状态，这个动作本身不会请求上游用量接口；上游数据的新鲜度取决于后端采样间隔和查询是否成功。手动查询成功后，发起查询的页面会立即刷新；其他可见页面通常在下一次同步时更新。隐藏的页面跳过定时同步，重新切回时立即同步。

### 查询返回 401

该账号的登录凭据通常已经失效。进入管理员模式，编辑账号并粘贴最新的 `auth.json` 内容。程序不会自动刷新 token；如果能从 token 中解析出过期时间，账号卡片会显示到期提示，并在剩余不足 2 天时提醒。无法解析过期时间时只显示凭据已设置，不能据此判断凭据仍然有效。

### 用量接口发生变化

项目使用 Codex 客户端实际调用的只读接口：

```text
GET https://chatgpt.com/backend-api/wham/usage
```

该接口可能随服务端更新而变化。程序会区分凭据失效、权限拒绝、限流、网络错误、超时、无效 JSON 和无法识别的字段结构。无法识别的响应不会写入历史；接口变化时需要更新解析逻辑。

### JSON 写入是否绝对不会丢失

程序先写入同目录临时文件，同步后再原子替换目标文件，可避免常见的半截 JSON 问题。单个文件替换是完整的，但多个数据文件之间没有数据库事务保证。

启动时，`accounts.json`、`snapshots.json`、`config.json` 和 `meta.json` 仅在文件不存在时使用默认值；如果文件无法读取、JSON 无效或顶层结构不符合要求，服务会报错退出并保留原文件。修复或从备份恢复后再启动即可。这是基础结构检查，并不等于校验所有嵌套字段。

单账号凭据文件采用不同处理：文件缺失、无法读取、JSON 无效或缺少 access_token 时，会视为没有可用凭据，不会因此停止整个服务；请在管理员模式下重新设置该账号的凭据。

## 安全说明

- 不要提交或公开 `data/`、`auth.json`、访问 token 或管理员密码。
- 凭据在本机以 JSON 文件保存，并非加密存储；应保护主机账号和文件权限。
- 登录 Cookie 在纯 HTTP 下没有 `Secure` 标记；反向代理到公网时必须启用 HTTPS，并检查代理和 Cookie 配置。
- 请求体最大为 1 MiB，超过限制返回 HTTP 413。
- 这是本地或可信环境工具，不是完整的互联网多租户认证系统。
